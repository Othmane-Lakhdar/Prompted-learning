# Controlled AI retrieval protocol v1

The selected route uses the installed Codex CLI with its existing ChatGPT login. Credentials are not read, copied, committed or printed. The M0 probe verified structured query/answer decisions and actual input/output token reporting; it is not a product benchmark. Exact attempt evidence is in [ai-route-probe.json](evidence/ai-route-probe.json).

The CLI's JSON event stream and structured final output are documented in [non-interactive mode](https://developers.openai.com/codex/noninteractive). Configurable shell tools, instruction files and context limits are described in the [configuration reference](https://developers.openai.com/codex/config-reference). Installed CLI help and actual probe results take precedence over an assumption that a listed feature works.

## Frozen inputs

Use [benchmark.json](benchmark.json), the versioned [instructions](benchmark-instructions.txt), and [decision schema](benchmark-decision.schema.json). Hash all three, the CLI executable/version, the model-catalog entry and effective invocation settings before a batch. Each of the 24 questions has five arms and three independent attempts: 360 scheduled trials. Do not replace these with one demonstration or ordinary design-review agents.

Every arm sees the same source snapshot, contexts, source policy, question and budgets. The source arm receives ordinary file discovery/search and source navigation over that immutable archive, plus capture/context/collection-status metadata needed to interpret it; it receives no extracted entities or analysis. P1–P4 receive their named profile and the identical source fallback. No arm receives expected answers, the field dictionary, compiler oracle dumps, the canonical database, other profiles or another attempt's transcript.

The controller supplies the same instruction text, a question ID/text and answer shape, representation rules, array-order semantics, allowed operations, the question's explicit context IDs/count scope and remaining budgets. These disclose formatting and type conventions, never gold values. Gold answers, accepted answer-specific examples and grading notes stay controller-side. The full pilot contains both contexts; questions about both languages require separately scoped retrievals. A one-context count is never compared to a summed two-context result.

## Decision loop

1. Start each attempt with an empty transcript and a new external working directory containing no source, profile, gold or repository instructions. Use a fresh CLI session for every decision; carry only this attempt's explicit controller transcript. Cached input accounting is recorded separately; cache hits are not reused answers.
2. Invoke `codex exec --ignore-user-config --ephemeral --skip-git-repo-check --sandbox read-only --json --color never --output-schema <schema> -m gpt-6.1-sol` with process-only config for `approval_policy="never"`, `features.shell_tool=false`, `features.shell_snapshot=false`, `features.multi_agent=false`, `features.view_image=false`, `web_search="disabled"`, `project_doc_max_bytes=0`, `model_reasoning_effort="low"`, `model_context_window=24000`, and the frozen `model_instructions_file`. No MCP/app server is configured. Supply the prompt through stdin and close stdin immediately. Do not change global configuration.
3. Accept exactly one well-formed decision and a successful `turn.completed` usage record. Reject actual command, MCP, web, file-change or other nonprotocol tool events. The read-only sandbox alone is not a claim of filesystem-read isolation; accepted model decisions have no direct evidence-access tool activity. Only the controller opens evidence.
4. A query decision has empty answer/citations and parses arguments as an object validated against the strict endpoint schema. The controller binds the selected arm/snapshot/context; model arguments cannot select arbitrary paths, change arms, query canonical data or relax budgets. It executes the query through the product service and adds the bounded response to this attempt's transcript.
5. An answer decision has empty operation/arguments. Parse its answer as a JSON object and validate exactly the question's keys/types. Citation IDs must have been returned in this attempt and resolve to supporting evidence. Check citation uniqueness in the controller: the provider rejects JSON Schema's `uniqueItems` keyword in its strict output subset (M0AI004). Preserve the full response even when validation or scoring fails.
6. Stop on a valid final answer, a timeout, protocol violation or exhausted budget. Record every scheduled trial and failure. Do not silently retry only unfavorable answers; a corrected transport or protocol creates a versioned complete rerun with the prior batch retained.

The controller exposes the strict `source-query/1` operations `source_capabilities`, `source_files`, `source_search` and `source` from contracts.json over the sealed `capture-index/1`. Each request binds the arm, snapshot, context and capture-index fingerprint. Discovery and literal ordinal case-sensitive search accept explicit logical path-prefix, file-role and file-version selectors; source retrieval uses exact archived byte spans. Every response declares budgets, coverage and delivery separately. Decoding failures and unvisited files remain visible. Cursors cannot cross arms, snapshots, contexts or capture indexes.

Source results cite `src/<base64url UTF8 file_version_id>/<start>/<end>/<sha256>`. All arms expose the identical coarse requested/supplied observation-input policy and its `capture/<indexhash>/policy/<policyhash>/<family>` citations, permitting uncertainty answers about build, artifact and runtime collection without consulting extracted facts. Discovery metadata does not invent source-span citations. The source engine reads only the immutable capture index and archive, never canonical/profile databases or gold. Queries never substitute the current working tree. Other endpoint names are exactly those in contracts.md; unavailable operations/details return structured reasons and coverage, never an invented empty success.

## Budgets and measurement

All arms use the exact limits in benchmark.json. Count every actual model input token, including repeated transcript and cached input, plus every output token across decisions. Cached input is a subset, not an extra addition. Reasoning tokens are recorded separately if exposed and not added twice when already included in output. Before another decision, check remaining time, query count and aggregate usage. A decision that crosses the aggregate token limit makes the trial budget-exhausted; do not accept its answer. This is an acceptance bound with measured overrun, not a promise of exact hard-stop token billing. Record overruns explicitly. No compaction or silent context truncation is allowed; a transcript beyond the selected context limit ends with a context-budget outcome.

Measure query latency/counts, returned records/bytes, source snippets/bytes, model usage and wall time per trial. Distinguish no-call zeros from unknown/unavailable measurements. Monetary cost is unknown for the current account route unless a usable price is supplied. The source archive counts toward storage even when a separate later structured-only experiment forbids retrieving it.

The fixed exposed model version is `gpt-6.1-sol`. The CLI does not expose an immutable hidden provider build revision. Preserve this as `not_exposed`, record the catalog entry hash before/after a complete batch, and report the reproducibility limit. A detected version/catalog/settings change invalidates cross-arm comparison and triggers a whole-batch rerun. No hidden backend equivalence is claimed; this adaptation is tracked in M0AI003.

## Grading and M1 gate

The expected facts and acceptable evidence were fixed before product outputs. Grade semantic atomic facts, separately count unsupported claims and missing facts, and require supporting citations. Apply the explicit equivalence and per-array ordering rules in benchmark.json. Formatting whitespace, known type aliases and correct paraphrases cannot silently become factual errors; wrong overloads and changed meanings must fail. Undisclosed internal reason-code spelling is never a scoring requirement. Novel correct-looking prose is sent to blinded evidence review, with the decision preserved. Report protocol/schema validity separately from semantic correctness. Strip profile labels and randomize trial records for independent citation review where practical. Any gold amendment needs a version, source justification and deviation entry; do not edit gold merely to accept a producer result.

Before the first comparison, M1 must demonstrate controller rejection of cross-arm/path overrides, invalid schemas, fabricated/unreturned citations, injected source instructions, nonprotocol tool events, missing usage, aggregate budget exhaustion, context-window exhaustion or compaction/truncation (including fixed CLI instruction overhead), deadline expiry and malformed responses. Grading tests must accept the frozen correct paraphrase/whitespace/set-order cases and reject wrong-overload and invented-runtime cases. It must also show distinct fresh attempt transcripts and prove profile-service isolation with canonical and other-profile files nearby. Route success without these tests does not complete M1.

Publish comparison.json plus a readable report containing every scheduled trial, grouped quality/cost variability, storage and production costs, unavailable features and the exposed-model limitation. Later milestones rerun the same questions when added capabilities affect them. Establish measured performance thresholds after M1 and before M5; never choose a winning profile in advance.
