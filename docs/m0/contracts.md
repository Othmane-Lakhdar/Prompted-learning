# M0 storage, analysis, export and query contracts

Status: design contract v1, awaiting the complete M0 gate. [schema.sql](schema.sql) is executable design DDL, not an implemented extractor. The [full inventory](../specifications/inventory.md), [implementation baseline](../specifications/implementation.md), and [task specification](../specifications/tasks.md) remain requirements. The field dictionary supplies item-to-column/producer/test traceability. An empty table is not evidence that its producer works.

## Field conventions

SQLite `STRICT` tables and foreign keys are mandatory; `PRAGMA foreign_keys=ON` applies to every connection. The DDL defines physical column types, mandatory values, primary-key order, foreign keys, explicit ordered collections, and checked shared vocabularies. The semantic validator below is additional to SQL constraints. No producer may replace a required normalized field with an extension JSON object.

| Convention | Normative rule |
|---|---|
| Identifiers | Opaque ASCII `kind:sha256hex` strings. Compare ordinally, never as labels. See construction below. |
| Text | Unicode scalar values with no unpaired surrogate. Preserve original spelling; no Unicode normalization. Source bytes are authoritative. |
| Integers | Signed 64-bit, bounded by field checks; counts and offsets are nonnegative. Overflow is an error, not wraparound. |
| Booleans | SQLite integer 0 or 1. Nullable boolean means a state must explain absence, never false by default. |
| Ordered fields | Child `ordinal` values start at 0 and are contiguous within the named parent/role. Multiple semantic collections may each start at 0. |
| Unordered sets | Deduplicate complete primary keys; serialized/query order uses stable keys. Never rely on insertion order. |
| Sizes/positions | Bytes unless the column explicitly says bits; spans are zero-based half-open. `duration_ns` is monotonic measured nanoseconds. `created_utc`/start/end times are ISO-8601 UTC strings. |
| Constants | `constant_kind` plus lossless textual value; e.g `signed_integer`/`42`, `string`/decoded scalar text, `null`/`null`. Do not coerce large integers, decimal literals or compiler floating constants into lossy JSON doubles. |
| Reasons | Nonempty stable reason code plus readable details in diagnostic/evidence. Reasons never change a failed or unmeasured value into a known value. |
| Child evidence | A child inherits owner scope and evidence unless it has an explicit evidence column; explicit child evidence supplements rather than discards owner context. |
| Nulls | A missing physical value needs an explicit `unknown`, `not_applicable`, or `not_collected` state unless a documented discriminator proves structural absence. Confirmed empty collections require `known` collection state. |

`field_state` is knowledge metadata, not an arbitrary value store. Its `field_path` identifies a physical scalar as `/TABLE/KEY/COLUMN`, where KEY is base64url without padding of the canonical JSON array of the row's complete primary-key values, in DDL primary-key order. For example the second argument of signature `sig:x` uses the `parameter` record's own ID; an `annotation_argument` row uses key `[annotation_id,1]`. Its state owner is the containing annotation record. The same grammar handles nonordinal composite keys. A collection path is `/TABLE/@collection/ROLE` on its owning record. ROLE is its actual relation (`arguments`, `members`, `modifiers`, `evidence`, etc.), declared in the dictionary. Unknown paths, nonexisting rows and ownership mismatches are validation errors.

For nullable child scalars, use their parent's registry ID and the complete row key. No single `arguments unknown` marker may mask a known argument with an unresolved parameter. A nonnull value is known; a simultaneous non-known state is invalid. Sparse union columns not selected by `type_kind`, `argument_kind`, `constant_kind`, etc. are `not_applicable` with reason `inactive_variant`. Confirmed semantic null is a known `constant_kind='null', constant_value='null'`, not SQL NULL. The `record.context_id` null is justified by `context_independent=1`; a null parent/cause pointer at a declared root is justified by that root's known structural role. All other unavailable scalars must have explicit metadata. Child rows that were never collected do not get invented placeholder values; the owner's collection state explains their absence.

For independently collected categories, ROLE includes the discriminator, e.g `context_setting:define`, `member_relation:declared_member`, `operation_child:condition`. The field dictionary declares the exact row filter for each role. Use JSON Pointer `~0`/`~1` escaping for literal `~`/`/` in ROLE. A known empty defines collection does not establish a known empty goals collection. A whole-table collection state cannot mask partially collected categories.

IDs, required source/coverage metadata and their states are retained across profiles. Metadata does not convert absent exported detail into a different knowledge state. `reference_availability` holds export visibility separately.

Shared entity kinds v1 are `namespace`, `module`, `class`, `struct`, `record`, `union`, `interface`, `enum`, `enumerator`, `field`, `global_variable`, `method`, `function`, `constructor`, `destructor`, `operator`, `conversion`, `property`, `indexer`, `event`, `delegate`, `parameter`, `local_variable`, `constant`, `local_function`, `lambda`, `type_parameter`, `value_parameter`, `template_parameter`, `alias`, `concept`, `label`, `scope`, `unsupported`. Generic/template definitions and specializations retain their underlying entity kind and explicit parameter/substitution/original-definition links. An unsupported placeholder is not accepted as complete support.

Shared relationship kinds v1 are `inheritance`, `interface_implementation`, `member_implementation`, `override`, `type_use`, `direct_call`, `candidate_call`, `construction`, `initialization`, `cleanup`, `read`, `write`, `callable_reference`, `callback_passing`, `event_subscription`, `event_unsubscription`, `event_invocation`, `delegate_invocation`, `generic_use`, `instantiation`, `specialization`, `annotation_use`, `include`, `module_import`, `macro_use`, `macro_expansion`, `alias`, `friendship`, `dynamic_reference`, `reflection_reference`, `native_interop`, `containment`, `declaration`, `definition`, `cross_snapshot_correspondence`. Type-use roles are `field`, `parameter`, `return`, `local`, `cast`, `constraint`, `exception`, `type_argument`. Other role values require their endpoint-family mapping in the dictionary. Unknown vocabulary values fail validation; they are not accepted merely because SQLite stores TEXT.

`entity.access` values are `public`, `private`, `protected`, `internal`, `protected_internal`, `private_protected`, `file_local`; inapplicable access is NULL with state. C++ linkage separately uses `external`, `internal`, `no_linkage`, `module`, `unique_external`; C# linkage is inapplicable. Parameter/call-argument passing uses `value`, `ref`, `out`, `in`, `ref_readonly`, `lvalue_reference`, `rvalue_reference`. A pointer passed by value remains mode `value` with a pointer type. Return passing uses `value`, `ref`, `ref_readonly`, `lvalue_reference`, `rvalue_reference`, `none` (void). Optional/variadic and implicit receiver facts are separate. File roles are `source`, `header`, `build_definition`, `resource`, `schema`, `template`, `script`, `documentation`, `support_other`.

Constant/default tags are `signed_integer`, `unsigned_integer`, `float_binary32`, `float_binary64`, `decimal`, `string`, `character_byte`, `character_utf16`, `character_utf32`, `boolean`, `null`, `enum`, `type`. Integer text is canonical decimal; IEEE floating values are exact fixed-width lowercase hexadecimal bit patterns with `0x`; decimal text is canonical signed coefficient plus `e` and decimal scale exponent; string text is decoded scalars; character text is a numeric code unit/scalar so a UTF-16 surrogate character literal is not an invalid JSON string; boolean is `true` or `false`; null is `null`. Enum text is canonical JSON `[type_id,integer_text]`; type constants are a referenced type ID. The matching expression/origin remains separate. `parameter.default_value_kind` tags `default_value`; missing default, uncollected value and a known null default remain distinct. No inference parses arbitrary default text as a constant without its tag.

## Source bytes and snapshots

The capture request names logical roots, physical paths, allowed generated-input roots, explicit exclusions and the internal/external/vendor boundary. Enumerate selected files deterministically, read exact original bytes, hash SHA-256, and copy bytes into `<run>/sources/sha256/HH/HASH`. `source_blob.storage_key` is `sha256/HH/HASH`, relative to the declared `<run>/sources` archive root; it does not include another `sources/` component. HH is the first two lowercase hexadecimal hash characters. The source manifest lists hash, byte length and storage key sorted by hash. Its own SHA-256 uses canonical serialization. Never use a moving working-tree path as retrieval fallback.

Root/file identity differs from content identity. Two paths with identical bytes have two `source_file` IDs but may share a blob. Root names are explicitly unique. Relative paths use `/`, have no empty, `.` or `..` components, and preserve observed case. Windows paths that collide under the filesystem's case behavior are rejected or proven aliases to one file; case folding is not an entity reconciliation rule. Symlinks/reparse points are not traversed implicitly: capture only after resolving within an allowed root, record aliases, and reject escape outside the declared boundary. Retain original path separately; absolute paths are operational locator data and are excluded from portable semantic IDs.

Before finalization, verify every retained file's hash and length against the archive. A read racing with modification is retried once using a stable read/metadata/hash check; persistent change fails that file with `input_changed_during_capture`. Parsing uses captured bytes, not a reread of current files. Additional internal includes/generated files discovered by a compiler return to T02 and must be captured before results are finalized. Finalized snapshots are never extended in place.

Supported source decoding in the pilot is strict UTF-8 (with or without BOM) and UTF-16 LE/BE with BOM. Record encoding and BOM length. Malformed or unsupported encodings retain bytes and a located failure diagnostic; decoding replacement characters are forbidden. A compiler's UTF-16 code-unit positions are mapped through an encoding-aware offset map back to byte offsets, including BOM and CRLF bytes. Reject positions inside a surrogate pair, incomplete encoded sequence, or outside `[0,byte_length]`. Clang spelling and expansion locations are captured separately; any transformed input buffer needs an explicit map to original bytes.

`source_span` `[start_byte,end_byte)` may be empty but must belong to an available retained file version and end at or below its length. A span is coordinates, not source text. Implicit operations use the causing construct's span, `implicit=1`, semantic role and execution point; never invent separate text. Generated in-memory input becomes a retained virtual `source_file`/`file_version` with its generator evidence and exact produced bytes. Generation and compiler synthesis remain distinct origins.

Source retrieval returns hash, file-version ID, encoding/BOM, selected byte interval, and either base64 exact bytes or decoded text. Decoded requests require valid character boundaries. Text line/column conveniences are derived and explicitly report whether columns count Unicode scalars or UTF-16 units; they never replace byte identity.

Archive integrity and query delivery have distinct lifecycles. `Seal` verifies all captured blob hashes/lengths before publishing the immutable index/manifest. Windows v1 `SourceArchive.Open` verifies index/manifest hashes and opens each unique available blob using read access with `FileShare.Read` (no write/delete sharing). It hashes and length-checks that same handle, resets its position, and retains the verified handle until disposal. Failure to obtain the sharing guarantee or any mismatch aborts Open; no weaker reopen-by-path fallback is allowed. Same-length tampering before Open fails SHA-256 verification. A concurrent writer/replacement is denied while the verified handle is retained; disposal ends the session guarantee.

Preparation uses a 65,536-byte hash buffer, at most 4,096 retained blob handles, at most 8,589,934,592 bytes verified, and at most 120,000 ms. These v1 limits are explicit configuration in preparation reports; exceeding any one fails Open and closes acquired handles. Preparation reports unique blobs, verified bytes, elapsed time, peak handle count and outcome separately from query metrics. Do not hide a whole-archive rehash inside a source query. Queries use position-independent reads or synchronized seeks on the pinned handles; charge actual bytes returned by archive reads, including overlap/snippet work, against source_bytes. max_source_bytes also caps source payload returned. Metadata-only source_capabilities/source_files perform no blob reads after preparation. All arms use the same preparation/handle policy and report its cost; operating-system cache effects are not represented as zero logical bytes read. Cross-platform implementations need an equivalent proven pinning guarantee or a separately bounded immutable copy strategy before support is claimed.

M1A amendment A001: a preparation report that fails or is cancelled before a trusted capture index supplies the source manifest hash uses `source_manifest_hash:null` and an explicit failure reason. A passed report requires the verified 64-hex hash. A fabricated zero hash never represents unknown data. The original reviewed M0 artifact hashes and the amendment record are preserved in [contract-amendments.json](../m1/contract-amendments.json).

## Identity and context

Define `H(domain, parts)` as SHA-256 of canonical JSON `[domain, ...parts]`, with an explicit domain-version string. IDs use the first family token plus the entire 64-character digest; no truncation. Retain the compiler key and identity scheme version separately. ID preimages are validated in canonical finalization; names never substitute for identities.

The normative domain/property schemas are `x-identity-recipes` and `$defs/identity-input` in contracts.json. In this contract `StableId.Create(domain, componentsObject)` passes one object as the variadic parts argument: the exact preimage is `[domain, componentsObject]`, with no trailing LF. It is neither `[domain, ...componentsObject.values()]` nor `[domain, [componentsObject]]`. Family is the domain before `/`; e.g `source_file/1` produces `source_file:HEX`. The layered table below is a reading guide to those exact schemas, not a competing recipe.

C# overloads, assembly identities, partial types and nested members follow compiler symbol identity. C++ redeclarations join only with compiler evidence; equal names, source text or hashes are insufficient. If reconciliation cannot be established, keep distinct provisional entities and `identity_reconciliation_failed` diagnostics; do not issue a false merged ID. `member_relation(role='declared_member')` links each member to its declaring type. Inherited-member queries traverse inheritance/implementation edges and preserve original ownership.

For the C# pilot's named declarations, the compiler key is Roslyn `ISymbol.GetDocumentationCommentId()` within the exact compilation/output identity; use compiler symbol equality when joining declarations, and preserve the complete signature as a collision check. Locals and anonymous declarations use their canonical owner plus source span/kind/ordinal because they do not have documentation IDs. A required supported declaration without a usable key fails that identity feature until its rule is implemented; qualified display text is not a fallback key. Native pilot declarations use `clang::index::generateUSRForDecl` on the canonical declaration, linkage domain and complete signature; conflicting declarations remain diagnostics. Tool/version changes are part of the identity policy.

`entity.identity_unit_id` records the actual C# compilation unit and is required for C++ internal/no-linkage identity. C# named entity hash identity uses context/output/compiler key, so this provenance pointer is not its preimage. It is inapplicable for reconciled external-linkage C++ entities; `entity_unit` lists every declaration/definition/use unit instead. Every appearance and body names its actual compilation unit. Body IDs include that unit because per-file options/macros may change body semantics even when declarations reconcile. Conflicting signatures/definitions block reconciliation; no arbitrary first unit becomes the entity's sole provenance.

`template_substitution` explicitly maps a definition parameter to ordered type/value/template/pack arguments. Defaults, pack expansion and reordered substitutions are not reconstructed by positional guessing. Unresolved dependent parameters retain their definition, known uses and state; no claim enumerates future instantiations. Cross-snapshot correspondence requires a separately evidenced relationship, never assumed ID equality.

A captured instance receiver is an implicit `parameter` entity linked to its callable by `member_relation(role='implicit_receiver')`, with receiver type, compiler identity and causing callable origin. It has no user-written signature parameter ordinal and is not added to `signature`'s explicit parameter list. Capture links refer to that storage identity, not the containing type or lexical scope. This representation and the corresponding receiver-capture fixture are prerequisites for claiming receiver capture support in later milestones.

Every registry record belongs to exactly one snapshot and either one context or an explicit context-independent scope. A shared fact that applies in several contexts is represented by contextual records sharing source identity, or by an explicitly context-independent object plus contextual membership rows. Context-sensitive semantic facts may not be marked independent for convenience. Redundant `context_id` columns must equal registry context. Combined views retain constituent contexts and cannot construct a path by switching contexts between edges.

### Acyclic identity construction and persisted inputs

Canonical IDs are assigned only by the host. Worker-local keys and compiler keys are not canonical IDs. Construct identity layers in this order; typed foreign-key links are filled only after the needed IDs exist. A foreign-key cycle does not justify a hash-preimage cycle.

| Layer | Exact identity inputs | Explicitly excluded dependencies |
|---|---|---|
| Snapshot | Repository logical identity; normalized logical root/boundary/exclusion definitions; sorted logical file paths plus exact hash/availability/origin descriptors. | source_root IDs, times, physical root locations. |
| Root/file/version | Snapshot ID + logical root definition; file uses root logical name/path; file version adds exact content/availability descriptor. | Entity/body IDs; file bytes are not a file identity alone. |
| Project/solution/tool | Snapshot plus captured definition identity/project-system key; tool uses name/version/content-fingerprint descriptor. | Build-context IDs or observed action/run IDs. |
| Context | Snapshot/project identity, configuration/platform/framework/architecture/language version, normalized ordered options, primitive tool descriptors, primitive provider descriptors and captured generated-input fingerprints. | Context-scoped dependency row IDs, unit/entity/type/signature IDs. |
| Unit | Context ID, language, ordered main/source/header/reference-input primitive descriptors and output identity. | Entity/body IDs; unit input row IDs. |
| Span | File-version ID, start/end bytes, origin kind, finite primitive origin stack (file-version/range/kind tuples). | Body/operation IDs and cause-span IDs. Cause links are populated from stack suffixes after IDs exist. |
| Named entity | Context, C# output/assembly or C++ linkage domain, normalized compiler entity key and primitive compiler signature key. Locals/lambdas add owning entity ID and primitive source origin/ordinal. | type_node/signature/parameter-detail/body IDs. |
| Parameter entity | Owning callable entity ID + declared ordinal + primitive type/passing key; implicit receiver uses its explicit receiver role. | Documentation ID/USR is not required for a parameter; no guessed name key. |
| Type/signature | Type uses context plus finite primitive compiler type key. Signature uses callable entity ID plus primitive compiler signature key. | Named-entity/type/signature backlinks do not enter one another's preimages. |
| Parameter detail | Signature ID + explicit parameter ordinal. This ID is distinct from parameter.entity_id. | The signature preimage does not contain parameter-detail IDs. |
| Body | Owning entity ID + actual unit ID + body span ID + representation/body kind. | Child operations or CFG/result IDs. |
| Operation | Body ID + representation + deterministic compiler-local structural path + compiler kind + origin span key. | Parent operation/type/entity result IDs; these become payload links afterward. |
| Analysis/CFG/finding | Producer/policy version, scope/header IDs and fingerprint of persisted input bodies/CFG/settings; deterministic local result key. | Mutable result timestamps, future result versions, or hashes of records containing this result ID. |

A primitive provider descriptor contains provider kind, logical name, selected version/state, content fingerprint/state and normalized logical supplying location. A primitive compiler type key is a finite tagged tree for builtins/qualifiers/pointer/reference/array/function/generic arguments. Named-type leaves contain the compiler declaration key and primitive provider identity, not a canonical entity/type ID; recursive types terminate at a named leaf. A primitive signature key contains callable kind/name, ordered parameter type keys/passing modes, return type/passing, generic arity/primitive constraints, qualifiers/linkage/calling convention. Never substitute a display string for these collision checks.

Normalize only known path-bearing compiler options: each becomes an ordered descriptor `{kind:"path",option,root_key,relative_path}`; other tokens remain `{kind:"literal",value}` in original order. Bind root_key to physical locations separately for execution. Input roots, SDK roots and tool roots have explicit logical names and provider fingerprints. Do not normalize arbitrary string literals or unknown options by textual replacement. If physical path values affect language semantics (for example __FILE__ without an equivalent path mapping), retain the relevant path-sensitive primitive value/policy in the context or mark that feature unsupported; portable naming must not change program meaning.

Every canonical registry record has a registered `identity-input/1` extension containing its family/domain and complete canonical preimage. The envelope stores only the minimal typed identity inputs, not serialized entity/body/analysis payload. Domains and exact dependency layers are listed in contracts.json. Hash `CanonicalJson([domain, components])` without a trailing LF and use the full SHA-256 with the declared family prefix. Finalization reconstructs/compares components against persisted typed columns, capture/context descriptors and referenced identity-input records, then recomputes the ID. Unrecognized domains, cyclic references, mismatched compiler keys/signatures or missing inputs are errors. Context/provider/type primitive keys are therefore not ephemeral host memory.

Rows without their own registry identity (entity_detail, ordered children and join rows) use their declared complete SQL primary key and owner; they do not receive fabricated entity IDs. For other registered producer families, the per-family `<table>/1` domain uses an explicit matching family, snapshot/context, producer contract/version, persisted input fingerprint and deterministic typed local key. `x-identity-recipes` lists every exact positional local-key rule and count; the rule name is a schema constant. These domains preserve the agreed family prefix. The producer's local-key rule must be registered in the family/ownership matrix before emission; allocation addresses, timestamps, unordered traversal ordinals and display labels are forbidden. Canonical validation can recompute every stored ID from its persisted envelope; replaying compiler analysis is a separate semantic test.

Every snapshot has a same-ID registry record: kind snapshot, section BD0.1, context_independent=1, context_id=NULL, snapshot_id equal to its own ID. The snapshot typed row is inserted before its registry row in the staging transaction; the semantic validator requires the pair even though the DDL does not declare snapshot.id -> record.id. Its identity-input/1, field_state and record_evidence use this owner, including explicit state/evidence for nullable vcs_revision and local_modifications_included. The snapshot hash still uses only primitive captured root/file descriptors; registry backlinks are populated afterward and create no hash cycle. Dataset and export identities retain their separately specified fingerprint recipes. Generic discriminators absent from physical columns (source ordinal, compiler edge ordinal, observation key, fact variant) are minimal typed provenance in the registered envelope; verify source ordinals against retained origins and producer rules, while hashes of primitive values bind those values without embedding omitted payload. A hash never makes arbitrary optional fact text legitimate metadata.

Profile anchors deliberately omit identity-input and all other extensions. Their IDs are validated against the canonical dataset during projection and bound by its fingerprint; a consumer does not reconstruct omitted preimages or fetch hidden canonical payload. All tables may be inserted in a staging transaction with `PRAGMA defer_foreign_keys=ON`, including recursive type/signature backlinks. Before commit, both semantic validation and `PRAGMA foreign_key_check` must pass; no unresolved deferred FK may be committed.

## Typed compiler-worker interchange

`native-worker-request/1` and `native-worker-result/1` in contracts.json are the frozen native boundary. A request binds correlation/request fingerprint, captured snapshot/context/unit/index, exact worker/Clang identity, target/language compatibility, normalized options/path bindings, captured file versions with original bytes/encoding/hash and explicit resource budgets. The host validates hashes/allowed path bindings before launch. The native worker uses captured buffers under stable virtual logical paths; uncaptured internal includes are reported as discovery requests, never silently read from the current working tree. Declared external SDK/provider roots may be read for compiler interpretation but their implementations are not emitted.

Native input discovery and final acceptance are separate request phases. The host first assigns an unpublished provisional unit ID from the known main/input descriptor set and sends phase discovery. The worker returns consumed_file_keys (actual entered internal files, including the main file) plus discovery requests. Discovery semantic facts are discarded; only validated consumed-input/discovery/diagnostic evidence may plan the next pass. Capture missing internal files through T02, freeze the new capture generation if needed, recompute the unit ID from the actual consumed-input set and rerun. A newly consumed header already in the archive still changes the unit input preimage and requires a rerun. After the set stabilizes, issue phase final with expected_consumed_file_keys; accept only if the returned set matches exactly and no unresolved discovery remains. C# uses its compiler-declared complete source/reference input set, with the same final-set verification. At most eight discovery passes are allowed; instability fails the unit with input_discovery_not_stable. Neither discovery IDs nor facts enter canonical storage. Final request/result scope, hashes and consumed set must agree before publication.

Request fingerprint is SHA-256 of canonical JSON of the entire request object excluding only request_fingerprint, without LF. Compute semantic_input_fingerprint first as SHA-256 of `["native-worker-semantic-input/1", selectedObject]` without LF. selectedObject has exactly snapshot_id, context_id, unit_id, capture_index_fingerprint, worker, target, main_file_key, files, options, path_bindings, requested_features and expected_consumed_file_keys. Files retain every request file field except bytes_base64 (original_sha256 binds bytes); path bindings retain every field except physical_path. Correlation IDs and resource budgets do not enter semantic input identity. Context ID already binds provider content/tool options and any semantically relevant physical path values. Verify both recipes before starting or accepting a result.

Transport is one UTF-8 JSON request and one UTF-8 JSON result, each terminated by LF, on stdin/stdout; stderr is diagnostic text and cannot supply records. The worker emits no canonical IDs of newly discovered facts. All discovered spans/entities/types/signatures/appearances/bodies/operations/CFG blocks/edges/storage events have typed local keys, unique within the response. References use those exact typed keys. Returned file references use the request's file keys and original file-version mapping. Primitive compiler keys remain distinct from local keys and readable labels. The in-process C# adapter must obey the same typed result semantics even though it does not cross a process boundary.

The host validates request fingerprint/tool/scope equality, result schema, local-key uniqueness and target kinds, byte spans against original captured bytes, primitive compiler keys, complete coverage/discovery/error envelopes and referenced keys before accepting any records. Acceptance is atomic per unit; malformed/truncated/mismatched results or a process failure cannot partially populate the canonical dataset. A well-formed partial result may supply valid facts plus explicit unsupported regions, but it does not satisfy a declared supported-feature gate. A result claiming complete coverage with unknown/missing inputs is rejected. Cancellation/budget/error outcomes are explicit, never empty successful record arrays.

Native source operation keys come from deterministic AST paths rooted at each body. Maintain a pointer-to-local-key map for both Stmt and Decl nodes while traversing the captured AST; pointer values never appear in keys or persisted data. Expand DeclStmt explicitly to VarDecl operation children because declarations are not ordinary Stmt children. Preserve all four pilot implicit casts (condition read, function-to-pointer callee decay, argument read, return read), their compiler kinds, conversion roles and causing spans. Their source-operation keys remain distinct even when spans overlap.

For Clang CFGStmt, map the referenced AST pointer through that exact map. Never join CFG operations by span+kind. CFG terminator/condition references use their original AST pointers; true/false successors and return-to-exit edges are explicitly labeled and carry the condition operation key when applicable. Every CFG member has block ordinal, member ordinal, source-operation key and correspondence/phase metadata. Unsupported CFG element kinds or missing/ambiguous map entries produce a located partial result and block the corresponding supported fixture.

Roslyn CFG uses transformed IOperation instances. First map with original SyntaxNode identity, OperationKind, primitive symbol/type/conversion key, implicit flag and semantic role/subtree signature within the same body; accept only exactly one source candidate. The pinned pilot has 16 CFG descendant operations, all distinct IOperation objects, with unique source SyntaxNode+OperationKind candidates; retain the stronger checks so this does not become a general span heuristic. Ambiguity fails the affected mapping. Compiler-introduced flow-capture/other lowered nodes need explicit separate lowered representation/key/origin contracts before support; they are not attached to an arbitrary source node.

Include BranchValue/terminator evaluation even if it is absent from the compiler block's ordinary operation list. The pinned Roslyn Choose CFG has six blocks: block 1 WhenFalse conditional successor 3 is false, fallthrough 2 is true; block 4 BranchValue reads result and its return edge reaches exit block 5. These labels come from branch semantics, never successor array position alone. Native and managed block numbering need not match; branch/call/definition-use facts must.

The wire explicitly carries ordered entity_modifiers, annotations with written builtin name/syntax/typed arguments, and preprocessing events with captured file/span/include target keys. This covers the pilot public/static/partial C# modifiers, native declspec(noinline), and the Arithmetic.hpp include edge without a generic JSON payload. Annotations map builtin C++ names to cpp-attribute/1; managed attributes use their resolved type. The request explicitly selects source_semantics, cfg and/or storage_events. source_semantics is required; storage_events requires cfg. M1B requests only source_semantics and may emit empty control_flow plus not_attempted/not_requested coverage for CFG/events. M1C requests CFG/events only after the M1B gate. A complete result means all requested features completed, never that an unrequested producer ran. Per-file coverage is partitioned by parse/entities/types/modifiers/annotations/preprocessing/operations/control_flow/storage_events. Empty arrays establish absence only with complete coverage for that feature; unsupported producers are not_attempted/partial with reason. Broader preprocessor/attribute semantics remain later gates. Failed/not_attempted CFGs may have null entry/exit with explicit reason and no invented blocks; complete CFGs require correctly typed entry/exit nodes.

Each CFG block also carries a deterministic ordered storage-event sequence for the common data-flow producer: parameter-entry definitions, reads, writes and unknown effects. Events identify storage entity, source operation/origin and phase. Deduplicate by `(block,source_operation_key,event_role,storage_key)` within a block when the compiler lists both child CFG elements and an enclosing subtree. Read RHS/condition/argument/return values before the corresponding write; an assignment destination is not a read unless the language operation reads its old value. The host consumes this sequence once and must not recursively replay every CFG operation subtree, which could create a false self-reaching definition for x=x+1. Compiler adapters validate event order against their evaluation model; unsupported ordering remains partial. Data-flow input fingerprints derive from persisted body/CFG/settings identities; the event sequence is a declared deterministic adapter derivation, not an unrecorded independent input.

### Transport-neutral host result (M1B amendment A002)

The additive `semantic-facts` and `semantic-unit-result` definitions reference the existing native result property schemas without changing native request/result definitions. A native result first passes its exact wire validation and is then normalized into this host carrier. The in-process Roslyn adapter uses truthful producer name/version/compiler version/binary hash metadata; it never invents a Clang identity. Scope, source index, semantic-input fingerprint, consumed inputs, status and all typed fact arrays remain explicit. Schema validation is followed by common semantic validation before canonical ID allocation or persistence. See `docs/m1/m1b-design.md` and the amendment record for the managed fingerprint recipe and M1B-only feature gate.

## Evidence and completeness

`record` is the minimal addressable registry, not a substitute for typed payload. Every included semantic record has exactly one matching primary payload table, and its `kind` and owning section match that family. Snapshot/source/context identities have registry metadata; the required snapshot pair and its acyclic construction are specified above. Child rows inherit their typed owner; no unattached facts are allowed. `record_evidence` supports multiple evidence items without duplicating facts. Source evidence resolves to captured spans; compiler/evaluation evidence identifies producer tool/version and the captured inputs; derived evidence identifies input record IDs and algorithm version.

Maintain independent dimensions: field knowledge; input selection; extraction/analysis status; export availability; query delivery. A complete extraction means complete only for the declared feature/region coverage. Each in-scope file and body has coverage. Unsupported constructs retain their source origin and a diagnostic; explicit unsupported does not count as passing a feature declared supported. Unknown counts stay null with state/reason, not zero. Skipped tests and unattempted analyses are not passes.

Canonical validation may finalize a dataset with declared partial analyses when all existing records are internally valid, scope/unsupported regions are explicit, required source identities are immutable, and no accepted support claim depends on absent results. An invalid record or unexplained missing prerequisite prevents finalization. Failed/cancelled runs remain diagnostic products and cannot be exported as successful datasets. Exporting all available rows never upgrades analysis status.

## External boundary

`external_symbol` retains only qualified identity/signature and supplying library name as descriptive information. Language, IDs, scope, source occurrences and evidence are technical support. No external bodies, member lists, docs, layout, inheritance inventory or expanded internal calls enter BD0. Compiler adapters may temporarily read external metadata. Package paths/versions/content hashes and target-framework/tool details belong to BDB, linked through evidence rather than copied into external descriptive fields. Unknown supplying library has `unknown` state/reason; a namespace is not automatically a library name.

Native C++ annotation spelling uses the registered language extension `cpp-attribute/1`, stored in `record_extension` with `schema_name='cpp-attribute'`, `schema_version=1` and the annotation's record ID. Its payload has `schema`, `written_name`, nullable `namespace`, and `syntax` (`double_bracket`, `gnu_attribute`, `declspec`, or `keyword`). Common owner, source span, resolution and arguments remain in `annotation`/`annotation_argument`; the extension does not replace them. For `[[deprecated("use New")]]`, retain written_name `deprecated`, namespace null, syntax `double_bracket`, and the known string argument `use New`. A builtin C++ attribute has no C#-style attribute class: `attribute_type_id` is NULL with `not_applicable` and reason `builtin_attribute_has_no_type`, not an unresolved or fabricated type. Entity-detail query annotation output reads this registered spelling extension; it never guesses a type from the attribute name. Unsupported attribute syntax retains its source span and explicit coverage rather than claiming resolved support.

## Operations and analysis

M1 declares one semantic representation per ordinary callable body; source syntax and lowered representations remain distinct enum values and cannot be mislabeled semantic. The pilot covers ordinary named functions/methods, parameters and locals, integer/bool literals, direct references and calls, local initialization/assignment, arithmetic/comparison, block/if/return, and a simple loop only when its fixture and bounded convergence checks pass. Unsupported syntax retains origin and partial coverage. C# async/yield/dynamic/unsafe and C++ exceptions/templates/macros/indirect calls are expansion-gated, not silently treated as ordinary direct code. The root support matrix and fixtures choose the exact accepted subset; this paragraph cannot expand it without those gates.

Operations have versioned kinds: `block`, `variable_declaration_group`, `variable_declaration`, `variable_declarator`, `expression_statement`, `argument`, `literal`, `reference`, `assignment`, `binary`, `unary`, `conversion`, `invocation`, `return`, `if`, `loop`, `jump`, `throw`, `try`, `handler`, `await`, `yield`, `initializer`, `implicit`, `unsupported`. `compiler_kind` retains the exact Roslyn OperationKind or Clang AST node kind; `operation_kind` is the shared semantic classification. Compiler wrappers/implicit conversions are not erased to make both languages' trees identical. Adapter-specific kinds require a mapped contract and fixture before acceptance. `operation_child` preserves nesting/order; `operation_operand` records semantic roles and parameter mapping without conflating source-child order and evaluation order.

For the frozen `Arithmetic.Choose` fixtures, the body root is the Roslyn body `Block`/Clang `CompoundStmt`, not an additional method-declaration wrapper. C# child order is declaration group, conditional, return. Its declaration group contains declaration then declarator (`result`, no initializer). The conditional contains the greater-than binary (`value`, literal 0), true expression-statement/assignment (`result`, invocation Add with two Argument wrappers containing `value` and literal 1), and false expression-statement/assignment (`result`, literal 0). Return contains the local reference `result`. Clang root children are DeclStmt with VarDecl (`result`, no initializer), IfStmt, ReturnStmt. The condition is BinaryOperator `>` with ImplicitCastExpr LValueToRValue over DeclRefExpr `value`, then IntegerLiteral 0. The true assignment has DeclRefExpr `result`, then CallExpr whose children are FunctionToPointerDecay over DeclRefExpr Add, LValueToRValue over DeclRefExpr `value`, then IntegerLiteral 1. The false assignment has DeclRefExpr `result`, IntegerLiteral 0. ReturnStmt contains LValueToRValue over DeclRefExpr `result`. Retain conversion kind and implicit flag. The fixture oracle checks role/order/targets and explicit absence of an initializer; compiler diagnostic/compiler-kind discrepancies block acceptance rather than silently editing the oracle to fit output. Semantic tree assumptions must be checked against the pinned compiler before M1 gate acceptance.

M1 CFG is intraprocedural with compiler-produced block/edge identities, explicit entry/exit, ordered operation references and branch conditions. CFG edges mean possible structural transitions, not proven feasible execution. Missing exception/cleanup/resumption models are explicit partial coverage; they cannot be labeled complete for such a body. `established_impossible` requires separate evidence.

M1 data flow is the `definition_use` family for local variables/parameters under one context, using a standard monotone reaching-definition fixed point over the accepted CFG. At each assignment, generate that definition and kill earlier definitions of the same proven storage; join predecessor sets by union. Reads emit one `may` fact per reaching definition. Parameter entry definitions and literal initialization are explicit origins. A fact is `must` only if the declared policy proves the same definition on every feasible modeled incoming path; M1 may conservatively emit only `may`. Convergence requires equality of finite definition-ID sets; deterministic iteration order is block ordinal. Iteration/time/node limits produce partial outcome with reasons, never a smaller set labeled complete.

Calls, reference parameters, pointers and unknown shared-storage effects invalidate affected must/constant claims. An unmodeled call creates `unknown_effect`; it does not imply no writes. Other result families (`argument_parameter`, `return_caller`, `capture`, `shared_storage`, `alias`, `possible_target`, `constant`, `range`) have separate versioned producer/support gates. Aliases or ownership are never inferred merely from pointer syntax. No stored value is an observed runtime value.

Unknown-boundary coverage records with source locations/reasons are mandatory BD0.16 metadata attached to each affected analysis result. They survive result-family selection even if optional `unknown_effect` findings are omitted. Thus retaining definition-use findings never erases their external/unsupported boundaries through an export filter.

`call_site.selected_declaration_id` records compiler resolution separately from runtime candidates. A direct nonvirtual call may have one complete candidate under its assumptions. Virtual/interface/delegate/function-pointer/dynamic sites keep dispatch, candidates, candidate-set completeness and unresolved remainder. Property/operator/initializer/cleanup calls use their semantic origins even without ordinary call syntax. Caller-callee relationship deduplication never deletes occurrence IDs.

Reachability uses an explicit `root_policy`, root reason/evidence and allowed edge kinds. Library roots may include public API, exports, initialization and callbacks, but public visibility alone does not prove the root set complete. Store `reachable` versus `outside_computed_set`; feasibility needs independent evidence. Witnesses are ordered relationship references, not all possible execution paths. Unknown callbacks or external implementations remain boundaries.

Each result records input/dependency IDs, settings, version, assumptions, completeness and finality. Refinements create new result versions; they do not mutate a finalized result. M1 has no CFG/data-flow feedback refinement beyond its explicitly defined fixed point. Future mutually dependent analyses must declare their iteration strategy and stop conditions before implementation. Queries use finalized results unless a diagnostic mode explicitly requests unfinished work, which is outside baseline profiles.

## Grouping and build states

Physical directories, file views, namespaces/modules, projects/solutions, IDE folders and explicit architecture definitions have distinct `grouping.group_kind` values. Directory depth is relative to the selected view root (0). Rollup to depth i assigns deeper content to its ancestor at i; root-level files stay visible. Project membership uses evaluated `file_participation`, never a directory guess. Logical-folder definitions are not filesystem evidence.

Views record context membership, kinds, depth and generated/implicit/unresolved/candidate policies. Aggregate source rows enumerate underlying IDs. Pair counts deduplicate relationship endpoints and kind/context; occurrence counts deduplicate occurrence IDs; contributing entity counts deduplicate entity IDs; candidate-edge counts remain separate from calls. Whole-project totals deduplicate across overlapping groups. Summary and cycle rows retain input IDs, calculation version, context and input fingerprint. Refreshing creates a new result when any dependency changes.

Build acquisition begins with explicit evaluated VS2022/MSBuild contexts for the pilot. Original definitions/import order, effective property/item/metadata values and relevant history are separate records. `build_setting` is a versioned property/metadata map as well as normalized settings; unfamiliar settings are retained as named strings with evidence, not dropped. Ordered include/reference paths and options preserve order. `context_input` and `unit_input` point to captured response files; opaque path text is not sufficient.

Every evaluated item, including non-file `Reference` and `PackageReference` items, has a `build_item` identity keyed by context, item type, evaluation stage and ordinal, with its evaluated include value and defining evidence. `build_setting.item_id` is required for item metadata. Two items from one definition therefore cannot accidentally share metadata by matching property name. File items may link to participation; resolved reference/package items may link to dependencies. These links do not substitute for the owning item identity. The M4 item fixture must include two same-type non-file items with different metadata and preserve both owners.

Keep declared items, selected inputs, consumed-by-compiler inputs and observed-build consumption distinct. C++ compilation units name their main source plus actual included headers/modules; C# units name their assembly's source/reference set. A header listed in a project is not proof of inclusion. All dependent files discovered after evaluation are captured before finalization.

Planned build actions distinguish tool/task identity, MSBuild target name and produced artifact identities. Dependency edges distinguish consumes-output from explicit order. Generation records distinguish expected/generated/cache-restored/existing outputs and link source mappings to BD0 without duplication. Executions distinguish succeeded/failed/cancelled/skipped/cache-restored/unknown; skipped has no fabricated successful exit. Existing artifacts are not attributed to a run without observed production/recovery evidence. Planned dependencies and observed timing/concurrency are separate.

Artifact inspection records reported symbols/layout/mappings with evidence and gaps. Absence in a symbol table does not prove unreachable or optimized-away source. Rebuild comparison separately records source impact, predicted action work, observed action work/reuse and changed artifact hashes. No M4 producer is claimed implemented merely because these tables exist.

## Canonical serialization

Serializer ID is `pl-jsonl/1`. Each table row is a JSON array `[table_name,[column_value,...]]` in DDL column order. Rows are ordered by table name as UTF-8 bytes, then by the canonical serialization of complete primary-key values; no locale collation. Logical records spanning children include all owned child rows exactly once. UTF-8 has no BOM; each row ends with one LF. No optional whitespace. Strings escape only quotation mark, backslash and control characters: `\b`, `\f`, `\n`, `\r`, `\t`, and lowercase `\u00xx` for other U+0000-001F. Slash and non-ASCII scalars are unescaped. Unpaired surrogates are rejected. Numbers are base-10 integers without leading plus/zeros (zero is `0`); floats are prohibited in semantic rows. Lossless nonintegral values are tagged text as above. JSON null serializes SQL NULL; booleans remain SQL 0/1 in row payloads.

Named JSON objects embedded in rows use the same escaping and recursively sorted UTF-8 property names; arrays retain declared order. Unknown keys, duplicate keys and nonfinite numbers are errors. Required JSON schemas are `extract-config/1` (selected roots, contexts, boundaries, adapters and analysis settings), `analysis-settings/1` (family, policy version, model assumptions and explicit computation budgets), `export-policy/1` (below). A language/tool extension needs an explicitly registered name/version and field contract before use. Free-form extension JSON cannot satisfy an unmapped inventory requirement.

[contracts.json](contracts.json) supplies the machine-readable Draft 2020-12 schemas for these named documents and the query/response envelopes. Cross-field identity, scope, budget and field-dictionary checks remain normative semantic validation in addition to JSON Schema. Response items must satisfy their registered typed record dictionary; an open JSON object in the envelope schema does not permit unregistered facts.

Semantic dataset fingerprint hashes schema/vocabulary/serializer IDs, captured source manifest, normalized effective configuration, and canonical semantic rows. `fingerprint-policy/1` excludes entire `dataset`, `export_profile`, `export_section`, `export_unit`, `export_omission`, `reference_availability` and `file_path` tables. It excludes columns `snapshot.created_utc`, `source_root.original_path`, `source_file.original_path`, `tool.path`, `build_context.working_directory`, `analysis_run.started_utc`, `analysis_run.ended_utc`, `build_run.started_utc`, `build_run.ended_utc`, `action_execution.started_utc`, `action_execution.ended_utc`, `action_execution.duration_ns`, `action_execution.observed_sequence`, `action_execution.concurrency_group`. Excluded columns serialize as a fixed `{"excluded":true}` token in their original position, so column order remains stable. State metadata addressing those excluded columns is likewise excluded; source-file names/relative paths and effective compiler settings remain included. No other column is excluded implicitly. `dataset` configuration/source-manifest fingerprints are hashed in the prefix before row serialization, preventing the whole-table exclusion from hiding policy changes. Actual observations such as build outcome, exit code, source hashes and tool versions remain semantic evidence. Dataset ID is `dataset:H(fingerprint-policy/1,semantic_fingerprint)` after finalization; operational attempt IDs are separate. Identical final canonical data/policy produces identical semantic payloads and omissions; identical SQLite file bytes are not promised.

## Projection and size policy

Every profile has the same schema DDL and reads one finalized canonical dataset. Source archive/contexts/analyzer results are identical across P1-P4. P1 disables BD0.7/12/13; P2 disables BD0.7/12; P3 disables BD0.7; P4 disables none. All other sections are enabled. Included baseline sections have unlimited optional payload budgets. Export does not rerun analysis, change retained call targets or relabel knowledge/coverage.

Policy v1 is `{schema:"export-policy/1",baseline:"P1"|"P2"|"P3"|"P4",sections:{"BD0.7":S7,"BD0.12":S12,"BD0.13":S13}}`. Each section requires `enabled`, `selection` (`"all"` or exact ID array), `payload_bytes` (nonnegative integer or `"unlimited"`). S7 also requires `max_nodes_per_body`, `total_nodes`; S12 requires `max_blocks_per_body`, `max_edges_per_body`, `total_blocks`, `total_edges`; S13 requires `families` (`"all"` or exact family array), `max_findings_per_unit`, `total_findings`. Every cap is explicit integer or `"unlimited"`. Unknown keys/IDs/families, negatives, duplicates, and nonempty selection for a disabled section are errors. Disabled sections use empty selection/families and zero limits. An absent user selection normalizes to `"all"`; an explicit empty list means none.

Normalize all defaults before hashing. Baselines only use their exact prescribed settings. Any changed inclusion/selection/cap/family setting gets ID `P?-variant:HASH`, never a bare baseline label. Body/analysis-unit selectors include context in their identity. Normalized policy fingerprint includes the serializer/version and all selections/caps.

Whole units are: BD0.7 all operation/tree/operand rows for one body representation; BD0.12 all blocks/edges/block-operation rows for one body/result; BD0.13 one result family for one declared analysis unit, including required unknown-effect metadata. A mutually dependent multi-body result is one unit and cannot be split for size. Mandatory body, analysis result, scope/coverage/evidence/source identities are outside optional payload. Optional record counts count distinct operation, CFG block/edge or finding IDs; child/link rows count toward bytes, not extra nodes.

Apply family filter first, then sort stable keys `[context_id,unit_id,family]` by canonical UTF-8 serialization. Admit a unit only if all per-unit and remaining section caps permit the entire unit. Otherwise record all exceeded reasons and continue; zero admits no optional units even if empty. `payload_bytes` is the exact sum of `pl-jsonl/1` bytes of owned optional rows, not SQLite pages or text character counts. Identities/anchors/coverage, indexes, sources and packaging overhead are measured separately and cannot be silently removed to meet a payload cap.

A retained cross-section reference must resolve to retained typed payload, an omitted anchor or an unresolved reference. Omitted anchors contain only registry ID, minimal record kind/section, scope and source origin plus availability/reason. They never contain omitted literals, operands, child trees, block edges or findings. Retain anchors only for omitted targets referenced by retained rows; do not copy a catalog of every omitted node. Required source-origin spans referenced by such anchors are retained. Body/analysis headers identify omitted units; `export_unit.unit_id` points to those headers, not every omitted payload item. `unresolved_reference` is semantic uncertainty and cannot stand in for export omission.

### Exact table ownership and non-leaking closure

`x-profile-table-ownership` in contracts.json classifies every DDL table, its full primary key and exact owner/unit joins. It is normative for projection; a dictionary classification such as BD0.16 is not a table-wide copy rule. `mandatory_payload` and `mandatory_global` rows retain canonical values. `mandatory_header` body/analysis rows retain scope, producer policy, input fingerprints and completeness. `optional_payload` and its `owned_child` rows follow only their admitted whole unit. Child ownership tests presence of the owner's typed payload, never presence of its registry row. `member_relation` and `template_substitution` follow the actual typed owner even though their FK targets record.

The projection algorithm seeds mandatory typed payload and admitted optional units, expands only the matrix's owner joins to retained children, and copies only metadata authorized by the retained typed owner. It then follows outbound references: a missing optional target gets a minimal registry anchor plus its source origin, without expanding its type payload, children or metadata. Repeat reference closure only for the minimal anchor's own scope/origin links. Regenerate export/reference-availability rows from the selected payload and direct references. Do not apply a reverse-FK graph walk over the registry.

`field_state` scalar paths require the addressed row and column to be retained; optional child-row PKs and collection states disappear with their payload. Collection states are kept only for a retained collection's owner and admitted collection family. An omitted collection is represented by export_unit/export_omission, never by changing its canonical knowledge state. `record_evidence` and `record_extension`, including identity-input/1, follow retained typed owners only. Anchors authorize none of these rows. A retained identity-input may mention an omitted target ID only where its exact recipe needs that identity; it may not embed the target payload or independently fetch it.

Provenance evidence is retained only when referenced by retained payload/metadata. Its detail is NULL or an exact registered code from x-provenance-policy, with readable meaning supplied by that policy and producer identity; it is not arbitrary prose or a dump/summary of optional facts. Locators use only the registered schemes. A record:ID locator participates in minimal-anchor closure just like an FK. For this v1 contract, evidence.blob_hash may identify an explicitly captured source/input/build-log/artifact evidence blob; the input must exist before semantic analysis, and compiler AST/CFG/result dumps produced by this extraction are prohibited. Such captured input evidence has the same archive access and byte budgets for all arms. A derived explanation referring to omitted facts keeps an availability/source-origin reference (locator `record:ID`), not hidden payload text. Evidence referenced only by omitted owners is omitted. This restriction applies at canonical finalization so profile projection never edits retained evidence values. Mandatory diagnostic.message and coverage.reason may explain acquisition, actual compiler diagnostics, unsupported constructs and failures; they must not encode successful optional payload dumps or enumerate omitted structures. Source/compiler error excerpts remain valid diagnostics. Producers must follow this registered policy; synthetic forbidden-payload cases validate the obligation without claiming a universal prose classifier.

`analysis_result.guarantee_text` and `analysis_assumption.assumption` must equal the exact guarantee/assumption strings for their registered x-provenance-policy.analysis_policies entry, not lists of inferred facts, constants, operation IDs or edges. `analysis_dependency.input_id` may reference only body, build_context, compilation_unit, tool, analysis_result, root_policy or view_definition headers. Exact body/CFG/settings content is bound by input_fingerprint; dependencies must not enumerate every operation just to force it into an anchor. New producer policies/codes require a contract update before emission; free-text fallback is invalid. A retained result header therefore cannot expose omitted structure through assumptions, dependency rows, metadata paths, logs or extensions. Source origins and explicit completeness remain usable independently of omitted payload.

For P2, data-flow locations/IDs remain usable without CFG/operations; referenced operations become minimal anchors. For P3, CFG operation references remain ordered but following them returns omitted availability. Retained relationship/call/reachability conclusions stay canonically identical. Known canonical counts and exported detail counts are separate. Uncomputed totals are null with reason.

Package layout is `<run>/canonical/index.sqlite`, `<run>/sources/manifest.json`, content-addressed blobs, and `<run>/profiles/<profile-id>/{index.sqlite,manifest.json}`. Each profile manifest requires schema/vocabulary/serializer versions, dataset/snapshot/context/analysis IDs, semantic and policy fingerprints, normalized policy, source-manifest hash and declared relative archive location, section counts/availability, unit/omission reasons, inherited analysis coverage, validation outcome and actual file sizes. `comparison.json` and report belong to the experiment; failed profiles remain listed in the top-level run report. Shared archive bytes are counted once in shared totals and fully in each standalone package total.

Publish into a new immutable generation directory: finish transactions, checkpoint/close SQLite, validate foreign keys/schema/evidence/equivalence, hash and measure final files, then write manifest. Only after the generation is complete may an atomic same-volume replacement of a small `current.json` pointer make it current. A failed/cancelled generation leaves the previous pointer and files unchanged. Readers pin a generation ID for the session. Never overwrite an active profile's SQLite file in place. A destination lacking the required rename semantics produces a publication error rather than a weaker unrecorded fallback.

## Query contract

Wire schema `query/1` is JSON via a local stdin/stdout executable transport in the pilot. One request per invocation is sufficient; a later persistent transport must keep the same request/response semantics. No arbitrary SQL endpoint. The opened generation/profile is explicit; the process has access only to that profile database and its declared immutable source archive. Optional canonical mode is outside the baseline and must identify itself separately; it is not a fallback.

Request fields are exactly `schema`, `profile_id`, `dataset_fingerprint`, `snapshot_id`, `context_id`, `operation`, `arguments`, `limits`, and optional `cursor`. All except cursor are required. `context_id` is one exact context; operations over context-independent source still bind that context's dataset. Unknown fields/IDs and cross-scope IDs are rejected. `limits` requires `records` (1..1000), `response_bytes` (1024..1048576), `time_ms` (1..60000); graph operations also require `nodes` (1..10000) and `depth` (0..16). Limits bound delivery/computation without modifying stored records. Source byte requests additionally require `max_source_bytes` (0..1048576).

Exact source selectors and result IDs cannot be guessed from display names. Profile queries cannot load omitted details from the canonical database; process-open-file tests must verify this isolation in M1.

## Source-only capture and query contract

The primary benchmark source arm and every P1-P4 source fallback use one source-only implementation and identical policy. Its only inputs are a sealed `capture-index.json`, the referenced source manifest and immutable blobs. It must not open a canonical database, any profile database, field dictionary, semantic oracle, expected-answer file or another arm's outputs. The controller binds an arm to the same frozen index; the source implementation does not inspect a profile to establish that binding. The normal profile `source` operation delegates to this same byte retrieval engine.

T02 creates `capture-index/1` before source analysis. The index records schema/version, snapshot ID, source-manifest hash, explicitly selected context IDs and file records containing file/version IDs, logical root/path, source role/language/origin, hash/byte length, byte-collection status and reason, encoding/decoding status, and context-specific included/excluded/undetermined selection with its reason. These are capture/evaluation metadata, never symbol, operation, dependency-graph, reachability or analysis-result facts. Project definitions and ordinary source remain readable through captured files. The index and source manifest contain no absolute working-tree fallback paths.

The index also retains explicit collection-input policy for `build_observation`, `artifact_inspection` and `runtime_observation`. Each family declares `requested`, the exact `supplied_file_version_ids`, `collection_state` (`not_collected` or `evidence_supplied`) and a nonempty reason. This describes the request and supplied inputs only, not whether a build succeeded, an artifact exists, or runtime behavior occurred. For M1 all three are requested=false, supplied IDs=[], state=not_collected, reason=`not_requested_and_no_supplied_evidence`. Do not infer that status merely from inability to open a semantic database or from no matching filenames. Supplying an evidence file changes state to evidence_supplied but does not establish its contents' truth, completeness or interpretation. Supplied IDs must refer to captured available files in the selected contexts. The BDR scope remains deferred; requesting runtime collection is not authorized by this metadata schema.

`collection_policy_fingerprint` is SHA-256 of canonical JSON for the whole collection-policy object plus final LF. The identical object and fingerprint are exposed to every arm by source_capabilities. Its citation is `capture/INDEX_SHA256/policy/POLICY_SHA256/FAMILY`, with lowercase 64-hex digests and FAMILY one of the three keys. Validate both hashes and return only the selected policy entry as citation evidence. The index stores the policy/hash but not its self-citation, avoiding circular hashing. These citations support statements about collection requests/supplied inputs and nothing about semantic conclusions. Any policy or evidence-input change requires a new sealed index for all arms.

Index file entries are sorted by `(logical_path UTF-8 bytes, file_version_id ASCII)`; each logical path is root-name plus `/` plus normalized relative path. Context membership entries are sorted by context ID and unique. The index fingerprint is SHA-256 of canonical JSON for the entire index, with `pl-jsonl/1` escaping/key ordering and one final LF; it does not contain its own fingerprint. A source request verifies that fingerprint and the referenced manifest. Available blob hashes/lengths must match the manifest. A file with captured bytes can still have invalid, unknown or inapplicable decoding. Excluded/unavailable input metadata keeps explicit reasons and never fabricates a content hash or empty bytes.

The fixed layout is `<run>/sources/capture-index.json` beside `<run>/sources/manifest.json`; blob paths resolve from that declared immutable archive root. Neither request arguments nor cursors can override these paths.

T03 discovery of additional required input returns to T02: create a new sealed capture index/snapshot and restart affected provisional analysis. Never append to an index already used by accepted analysis. All benchmark arms use the exact final index that preceded the accepted analysis pass. This keeps the source arm independent of the canonical database while preserving the same input boundary.

Wire request `source-query/1` has exactly `schema`, `arm_id` (`source`, `P1`, `P2`, `P3`, `P4`), `capture_index_fingerprint`, `snapshot_id`, `context_id`, `operation`, `arguments`, `limits`, and optional `cursor`. All except cursor are required. There is no dataset/semantic ID selector. Limits require `records` (1..1000), `response_bytes` (1024..1048576), `time_ms` (1..60000), `source_bytes` (0..1048576). Source bytes count actual archive bytes read, including search overlap/snippet reads; metadata-only discovery reads zero source bytes. Metadata/index parsing still counts time and response size. Limits and query parameters are identical across arms.

| Operation | Exact arguments | Permitted output |
|---|---|---|
| `source_capabilities` | `{}` | Source API/serializer versions, the four source operations, collection/decoding counts and statuses, explicit collection-input policy/fingerprint/citations, supported source formats and hard limits. No semantic feature, entity, relationship, flow or analysis coverage. |
| `source_files` | `path_prefix`, `roles`, `file_version_ids` | Bounded captured file metadata for the selected context, including unavailable/excluded reasons. `roles` and file IDs are `"all"` or an exact unique array; empty array selects none. |
| `source_search` | `text`, `match_kind="literal"`, `case_policy="ordinal_case_sensitive"`, `path_prefix`, `roles`, `file_version_ids`, `snippet_bytes` | Bounded literal match intervals/citations, readable logical file labels, optional bounded snippets and explicit scanned/unsearchable/unvisited coverage. `snippet_bytes` is 0..4096. |
| `source` | `file_version_id`, `start_byte`, `end_byte`, `format` (`bytes`, `text`), `max_source_bytes` | Exact archived byte interval or strict decoded text with the same hash/span contract as profile source retrieval. Effective source-byte cap is min(request limit, max_source_bytes). |

Path prefixes are literal ordinal prefixes of the normalized logical path, with `/` separators; absolute paths, backslashes, `.`/`..` components and source-root escapes are invalid. Empty prefix means all permitted paths. Role values are the file-role enum above. Unknown file-version IDs or IDs outside the requested snapshot/context are errors even if another filter would exclude them. Search/retrieval only accesses `included` file versions with available bytes; metadata discovery may expose other capture statuses. Undetermined selection is not silently treated as included.

Search text is nonempty, at most 4096 Unicode scalars, without normalization, regex syntax or locale/case folding. Decoding preserves BOM interpretation and original line endings. Search returns every matching start position, including overlapping occurrences, in file order then ascending start/end byte offset. UTF-8/UTF-16 positions are converted to exact original byte intervals, including BOM and CRLF; no byte position is guessed from character count. Snippets stay on valid encoding boundaries, are at most `snippet_bytes` original bytes, and include the match only when it fits. Otherwise snippet is null with reason `snippet_budget`; the complete match location/citation remains valid. Search never replaces malformed sequences with replacement characters. Undecodable/binary/unavailable files are explicitly unsearchable, while raw byte retrieval remains possible for available bytes.

Large files are scanned incrementally with sufficient overlap to find a literal spanning a chunk boundary. A continuation stores the next unexamined candidate byte position on a valid character boundary; it neither repeats nor skips candidates. Actual repeated overlap reads count against the next request's source-byte budget. If budgets cannot make progress on one candidate/item, return `budget_exceeded`/limited rather than an endlessly identical more-pages cursor. If time or read budget ends early, unvisited/partially scanned files remain explicit. A complete no-match claim applies only to the selected searchable range; unsearchable files prevent claiming complete source coverage.

The source response `source-response/1` echoes arm/index/snapshot/context/operation and request fingerprint. It has `status`, typed `items`, capture/scan `coverage`, `delivery`, measured `metrics` and diagnostics. Status is `ok`, `unavailable`, `invalid_request`, `invalid_cursor`, `budget_exceeded`, `failed`. Coverage is strictly collection/search coverage, never extraction or analysis coverage. `source_files` emits only the requested context membership, not facts assembled across contexts. Response envelopes and indivisible items must fit response-byte limits; no partial JSON items. `source_capabilities` cannot be redirected into normal semantic `capabilities`.

Source cursors are base64url canonical JSON `source-cursor/1`, binding arm, capture-index fingerprint, snapshot, context, operation, request fingerprint (all request values except cursor), logical file order key and next candidate byte offset. Validate the decoded schema and all binding values; changed filters/limits/index/context/arm invalidate the cursor. Metadata pages resume after the last file key; search pages resume at the next candidate position. No cursor permits reading a caller-supplied filesystem path. A missing/corrupt continuation fails explicitly. Hash/checksum is corruption detection, not authorization.

Source citation IDs are exactly `src/FILE_VERSION_BASE64URL/START/END/SHA256`, where the file-version ID is UTF-8 then base64url without padding; START/END are canonical nonnegative decimal byte offsets; SHA256 is 64 lowercase hexadecimal characters. Structured citation fields repeat file_version_id, content_hash, start_byte and end_byte. The match/retrieval bytes must equal that immutable interval; citations are independently checked against the same capture index/archive. Metadata-only file rows have no invented source-span citation. These citation IDs are shared across arms and are valid independently of profile payload availability.

## Validation and stage gates

Schema construction passing is only an M0 design check. Before canonical finalization, validate: required row family and section ownership; ID preimages; registry/typed-row bijection; scoped FKs and compatible contexts; every source span and archive hash; child order/acyclic trees; field-state path/owner/value consistency; evidence resolution; allowed relationship endpoint kinds; external boundary; analysis final/dependency consistency; and coverage for every selected file/region. Registry references to nonexistent payload are invalid except explicit unresolved references. Duplicate or conflicting compiler identities fail reconciliation rather than merging.

Relationship endpoint contract uses these exact sets: E = every entity kind above except `unsupported`; T = class/struct/record/union/interface/enum/delegate/type_parameter; C = method/function/constructor/destructor/operator/conversion/local_function/lambda; S = field/global_variable/parameter/local_variable/constant/enumerator/property/indexer/event; O = operation record; F = source_file record; P = preprocessing record; X = external_symbol record; U = unresolved_reference record. Where E/T/C/S occur, the registry kind must be entity and its entity_kind must belong to that set. An external or unresolved target is admitted only where X/U is explicitly listed. These permissions do not assert that every kind is supported by the current producer.

## Function-type signature ownership (A003)

The existing `signature/1` entity-owned components remain unchanged. Its additional alternative is `{function_type_id, compiler_signature_key}`. The owner must resolve to `type_node(type_kind=function)` whose primitive key has that exact signature; `signature.callable_id` stores the type ID and `callable_kind` is `function_type`. The type's `function_signature_id` must point back to that exact signature. Build the type ID from its finite primitive first, then the signature ID; the payload backlink never enters the type preimage. A cyclic payload reference is permitted, a cyclic identity preimage is not.

Abstract function-type parameters derive ordered type/passing facts from the primitive. Their entity, source name and defaults are null with `not_applicable` states; no declared parameter entity is fabricated. Abstract signatures have `body_state=absent` and no body. Same primitive function types share their abstract signature while separately named callable signatures remain distinct. No native wire change or later-stage producer is introduced.
